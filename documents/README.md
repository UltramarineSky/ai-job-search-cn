# 你的材料放哪里

**文件不要放在这个目录下。** 这份说明留在仓库根，但材料是**每个人各自**的，
要放进你自己的目录：

```
users/<你的名字>/documents/
```

`<你的名字>` 就是仓库根 `.active_user` 里那一行。不确定是谁，跑一次自检：

```bash
python tools/doctor.py
```

> 为什么不放仓库根：多人可以共用一份 clone，各自的数据分开存。放到根目录的话，
> 别人能看见你的简历，而且 `/job-setup` 也不会去那里找。

---

## 放什么、放哪个子目录

| 子目录 | 放什么 | `/job-setup` 从里面读什么 |
|---|---|---|
| `cv/` | **你现在的简历**（最完整的那一版，不用为这个工具改）；**招聘平台上的在线简历也放这儿**，见下 | 工作经历、教育、技能、项目 |
| `linkedin/` | 领英资料导出（有就放，没有就算了） | 自我介绍、推荐信、技能背书 |
| `diplomas/` | 学历证书、成绩单 | 学历层次、院校、专业——**硬性条件要用** |
| `references/` | 推荐信、离职证明 | 别人对你的评价（写进「行为特质」） |
| `postings/` | 抓不到的职位页，自己粘成文本 | 文件名写「公司 - 岗位.txt」，正文是完整职位描述。**它不会被自动读取**，见下面那条 |
| `applications/` | **工具自己写的**投递材料，一个岗一个文件夹 | 不用你手动放 |

> **`postings/` 里的东西不会被自动读走 —— 要投它的时候把正文交给 `/job-apply`。**
> 这一格是给「工具抓不到、只能你自己复制」的那些岗准备的（BOSS 直聘、智联、
> 前程无忧的职位描述常常就是这种）。放进去之后：
>
>     /job-apply <把那个文件的正文粘过来>
>
> **为什么不自动扫**：一个目录里的文本文件没有链接、没有公司字段、没有抓取
> 日期，进不了职位库的去重与排序；硬塞进去会得到一批和别的岗对不上账的条目。
> 所以这一格的定位是**你自己的存放处**，不是第二条抓取通道。
> 文件名那个格式也是为你自己 —— 一眼找得到，且和 `applications/` 下的命名对得上。
>
> （`/job-apply` 那头也写了这条：开口让你再贴一遍之前，先看一眼这个目录。）

> **别漏了你在招聘平台上已经填好的那份。** 猎聘 / BOSS 直聘 / 智联 / 前程无忧
> 的在线简历是**结构化必填**的（工作经历、项目、技能标签一栏栏填），多数人在
> 上面花的功夫比那份 PDF 多，写得也更细——项目里的具体动作、技能标签、
> 用过的工具，常常只在平台上有。
>
> 那几个平台都能把在线简历**导出或预览成 PDF**（各家入口在「我的简历」附近，
> 叫法不一）。导一份丢进 `cv/` 就行，和你的主简历放一起，多一份不冲突。
>
> 这一条对国内用户尤其值：`linkedin/` 那一行写着「有就放，没有就算了」，
> 而多数大陆求职者的经历**根本不在领英上**，在这四家里。

一个都没有也能开始——`/job-setup` 会改成直接问你。有简历的话省事很多：它读完再问，
只补缺的那些。

文件名随便取。同一类放了多份，`/job-setup` 会都读一遍并互相对照。
`cv/` 里请放**最完整的那一版**，不要放为某个岗改过的。平时投递发的就是你的主简历；
只有特殊情况才由 `/job-cv` 为某个岗现做一份。

## 支持什么格式

| 格式 | 能不能读 |
|---|---|
| `.pdf` | ✅ 能。**最省事的一种** |
| `.md` / `.txt` | ✅ 能 |
| `.tex` | ✅ 能 |
| `.doc` / `.docx` | ❌ **读不了**。Word 里「另存为 / 导出 → PDF」，再放进 `cv/` |
| `.jpg` / `.png`（简历截图） | ⚠️ 能看，但读出来的字容易缺漏，不如给 PDF |

> Word 是最常见的简历格式，而这里恰恰读不了——所以专门列出来。转成 PDF 只要几秒，
> 别把时间花在排查「为什么它没读到我的简历」上。

## 放完之后

```bash
claude          # 在这个目录启动
/job-setup          # 它会先说「我在你的 documents/ 里看到了这些文件」，再逐项跟你确认
```

`/job-setup` 是**可以反复跑的**：以后补了新材料再跑一次，它只会往上加，不会覆盖你已经
确认过的内容。

## `applications/` 里是什么

这个目录不用你管，工具自己写：

```
applications/<公司>_<岗位>/
├── posting.md          原始职位描述          ← /job-apply
├── evaluation.md       这个岗的评估          ← /job-apply
├── outreach.md         三个渠道的投递话术    ← /job-apply
├── cover-letter.md     求职信（只在需要时才有）← /job-apply
├── resume.pdf          为这个岗定制的简历     ← /job-cv，只有特殊情况才有
│                       （resume.typ 是它的源文件）
└── job-outcome.md      结果与备注            ← /job-outcome
```

## 隐私

`users/` 整个目录已经 gitignore，你放进去的东西**不会进版本库**、不会被推上去。
同一台电脑上的其他系统账号仍然读得到——真要保密，用不同的操作系统账号或各自 clone。
