# /job-dashboard —— 打开求职总览页（在本机起服务，数据不出这台机器）

起一个只监听本机的服务，把总览页开出来：流水线总览、可以投的岗位、逐岗展开的详情与
三渠道话术、每一步该敲的命令，以及**直接改投递状态的按钮**。

与 `/job-html-report` 的分工：本命令是**投前 / 投中的总览页**（现在该投谁、怎么投）；
`/job-html-report` 是**投后分析**（投递记录的统计与漏斗）。互补，不替代。

## 改了导出器就要重启服务

`serve.py` **同进程** import `export_web_data`——它用的是**启动那一刻**的代码。
所以改了导出器（加字段、改口径）之后：

```bash
# 停掉旧进程再起，否则它会用旧代码把 data.json 覆盖回旧格式
python tools/serve.py
```

> 不重启的症状很有迷惑性：手动跑一次 `export_web_data.py`，文件里新字段有了；
> 刷新页面，那块还是不出现——因为服务器在下一次自愈重导时又把它写没了。
> **看起来像前端没渲染，根因在服务端进程的生命周期。**
> 2026-08-13 实测撞上（新加的投后统计块「查无此块」，查了三轮才定位）。

## 前置检查

`.active_user` 缺失/为空 → 引导跑 `/job-setup`（新建首个用户）或 `/job-user`（查看/切换），
**停止**。面板是**某一个用户**的视图，没有活动用户时它没有可显示的对象。

## 你自己把它起起来，不要丢一个路径给用户

用户要看面板时，**你执行 `python tools/serve.py`**（后台跑，它会自己打开浏览器）。
没有执行权限就**开口要**——「我起一下本地服务打开面板，需要授权跑
`python tools/serve.py`」。

理由：新用户根本不知道该敲什么。让他自己去开等于把「怎么打开」这道题原样还给他。

> **别退回「产出一个 HTML 再把路径贴给用户」。** 没有服务时状态按钮整排不渲染，
> 一个岗上只剩「不投这个岗」——能标不投，标不了已投，用户点完以为记上了、刷新就没了。
> 原委见 `web/README.md`。

## Step 1: 起服务

```bash
python tools/serve.py
```

- **后台跑**，不要前台阻塞——它是个常驻服务，前台会把整个会话卡住。
- 起完**确认端口真的在应答**再报告，别报一个没验证过的「已启动」：

  ```bash
  curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:29029/
  ```

  返回 `200` 才算起来了。
- **已经有一个在跑时它不会再起第二个**，而是照实说一句就退出。三种情况三条路：

  | 它说 | 什么意思 | 你该做什么 |
  |---|---|---|
  | 「总览已经在跑了（某某）：<地址>」（退出码 0） | 端口上那个用的就是当前代码 | 把地址报给用户，别再起 |
  | 「…但它是在你改代码之前起的」+ 两行命令（退出码 1） | 那个进程是旧代码，页面上的按钮记不准 | 照它印的命令停掉旧的，再起一次 |
  | 「<端口> 被别的程序占着」（退出码 1） | 不是我们的服务 | 按它给的 `--port` 换一个，别去停别人的进程 |

  > 这一段是 2026-08-24 加的，起因是用户反复看到「这一页的服务还在用旧代码跑」。
  > 根因在 `SO_REUSEADDR`：**Windows 上第二个进程照样 bind 成功**，
  > 于是新进程印出「求职总览：…」、浏览器也开了，可连接仍归先起的那个。
  > 用户照页面说的按 Ctrl+C，杀掉的是**刚起的这个新的**，旧的原地不动。
  > 判据与实测见 `tests/test_a_second_server_does_not_shadow_the_first.py`。
- 第一次跑之前要构建一次前端：`cd web && npm install && npm run build`。
  只需要一次；缺 `web/dist` 时工具会把这句打出来。
- 数据不用手动刷：每次请求 `/data.json` 会比对上游 mtime，有更新就先重新导出，
  **刷新浏览器即最新**。所以新抓、新排序、新出材料之后，让用户刷新页面就行，
  不需要重跑任何命令。
- 读取（均为活动用户目录下的路径）：`job_scraper/seen_jobs.json`、
  `documents/applications/*/`、`job_search_tracker.csv`（可选）、
  `profile/candidate.md`（只判断就绪与否）。

## Step 2: 汇报

告诉用户地址（`http://127.0.0.1:29029`）与计数摘要，并说明**面板上能直接做什么**：

> 顶部有四个快捷卡片：
> 1. **招聘网站**：展示猎聘、BOSS直聘、智联招聘、前程无忧的抓取与简历刷新情况。特别注意：BOSS直聘与前程无忧网页端没有刷新入口，面板会醒目标注并提示「需开手机端 APP 刷新」，避免简历因长时间未更新而沉底；
> 2. **岗位类型**：提供外包、驻场、未公开公司等偏好过滤开关，一键清理视野；
> 3. **要装的工具**：检查 Python、Node、Typst 等关键依赖状态；
> 4. **命令手册**：汇总各求职阶段可用的推荐命令，随时速查。
>
> 每个岗展开后，材料备好的会有一个「复制开场白」按钮——点一下就进剪贴板，
> 粘到招聘网站的聊天框直接发，这是整页最常按的一下。
>
> 同一行上有状态按钮——还没投的是「我投了」，投过之后变成
> 「约面了 / 挂了 / 没下文」，再往后是「拿到 offer」「入职了 / 我拒了」。点一下
> 直接写进投递记录，可撤销。旁边还有「不投这个岗」，标错了到「不投的岗位」里
> 点「放回可以投」。
>
> 页面还提供投后统计（回复率、约面率、按分数段分析打分有效性）与拒绝原因分布。
> 要写清楚经过（归档、跟进话术、面试反馈复盘）仍然走 `/job-outcome <公司>`。

## 规则

1. **状态按钮是这条路存在的理由。** 它只做「改一个字段」这一件事，不接大模型
   （`serve.py` 自己的边界）；需要判断的 `/job-interview`、`/job-offer`、`/job-outcome`
   照旧走命令行，按钮点完会顺手把该敲的那条打出来。
2. **只绑 `127.0.0.1`。** 同一局域网的其它机器连不上；写操作带一次性 token，
   防的是「你在浏览器里打开的任何网站都能往 localhost 发 POST 把你的职位标成不投」。
3. **隐私。** 页面内联了职位、话术、薪资期望，属个人数据：只在本机服务上看，
   不提交、不上传、不发布为在线 Artifact。
4. **失败即停。** 工具报错时原样转告（最常见两种：还没构建前端、还没跑 `/job-rank`），
   不要试图绕过或手写 HTML 兜底。**尤其不要在职位数为 0 时硬起**——空数组会让界面
   回退到演示数据，产出一个满屏职位、却一个都不是真的页面。
5. **可选参数：** `/job-dashboard <用户名>` → 追加 `--user "<用户名>"`，**服务这个人的数据**
   （不改 `.active_user`）。`--port` 换端口（默认 29029，也认环境变量 `JOBS_PORT`）。
   端口被占时换一个，别去杀占用它的进程——那可能是用户自己开着的另一个面板。
