# /job-add-template —— 换一套简历 / 求职信模板

你在帮用户注册他自己的简历模板。框架默认使用 Typst 中文简历模板（`resume/template.typ`）；三渠道投递话术是纯文本，不涉及编译。这条命令让用户换上自己那套简历模板：把模板文件存起来、把用法问清楚记下来（用哪个排版引擎、什么字体、有哪些样式规矩、页数上限），验证它**真的编译得过**，再接进 `/job-apply`，让之后每一次投递都用它。

用户跟命令一起给的输入，可能带一个子命令、一个文件路径，也可能什么都没有。

下面这几步**按顺序**走。

---

## Step 0：解析参数

- 输入里带 `--list` → 跑下面的 **列出模式**，然后停。
- 输入里带 `--use <名字>` → 跑下面的 **切换模式**，再带着解析出来的模板信息进 **Step 5：激活**。 `--use default` 还原到框架默认模板——**按类型**删除对应的激活文件（还原哪一类、怎么问，见 Step 5 的还原规则）。
- 输入里带文件路径、或者 @ 了某个文件 → 把它当作模板来源，带进 Step 1。
- **没给任何参数** → 先跑 **列出模式**（列出已装模板与当前激活的那套），
  然后问一句「换一套，还是加一套新的？」，按答案进切换模式或 Step 1。
  一套都还没装时不必多问，直接说明并进登记流程。

  > **原来裸命令直接进登记访谈。** 而索引里给它的说明是「换一套简历 / 求职信模板」，
  > 用户照着说明敲，拿到的是一串「这套模板叫什么、引擎是什么、有哪些参数」的登记提问
  > ——他想换，工具在收表。**默认要对着说明**，不是对着命令名（`add-` 那个前缀
  > 是给写代码的人看的）。登记是低频动作，换是高频的。

### 列出已装的（**列出模式**）

用 Glob 匹配 `templates/**/TEMPLATE.md` 找出已登记的模板。逐个读它的清单文件，打印成一张表：

```
## 已注册的模板

| 名字 | 类型 | 排版引擎 | 字体 | 在用 |
|------|------|--------|-------|--------|
| <name> | 简历 / 求职信 | typst/xelatex/lualatex | <主字体> | 是/否 |
```

某套模板算**在用**，条件是活动用户的 `templates/active-cv.md`（简历）或 `templates/active-cover-letter.md`（求职信）存在、并且点了它的名（活动用户路径怎么解析见 `AGENTS.md`「活动用户与多用户」）。一套自定义模板都没有时就直说，并说明 `/job-add-template` 是用来登记的。到此停下。

### 换一套（**切换模式**）

输入里带 `--use <名字>` 时：

1. `<名字>` 是 `default` 时，跳过模板解析（`default` 不对应任何 `TEMPLATE.md`），直接带着 `default` 这个启用目标进 Step 5。 要还原的**类型**由 Step 5 的还原规则确定——用户在输入里说了类型（`--use default cv`、「还原简历模板」等）就照它，没说则按规则问清，不要默认两类都还原。
2. 用 Glob 匹配 `templates/**/TEMPLATE.md`，找**父目录名与 `<名字>` 完全相同**的那份清单。
3. 一份都没匹配上 → 停下，说这套模板没登记过，并建议跑 `/job-add-template --list` 看看有哪些。
4. 匹配上不止一份 → 停下，把匹配到的清单路径都列出来，请用户改名其中一套——**激活这件事不许有歧义**。
5. 读匹配到的那份 `TEMPLATE.md`，取出：
   - **类型：** `CV` 或 `Cover letter`
   - **引擎：** `typst`（默认）、`xelatex`，或 `lualatex`
   - **页数上限：** `<N>` 页
   - **字体：** 那一整行字体说明
6. 从清单路径推出模板目录，确认骨架文件就在同一个目录里（typst 是 `template.typ`，LaTeX 是 `template.tex`）。**不在就报错停下**——那说明这套模板没登记完整。
7. 从清单路径推出 Step 5 要用的 `<类型>`：
   - `templates/cv/<名字>/TEMPLATE.md` → `cv`
   - `templates/cover_letters/<名字>/TEMPLATE.md` → `cover_letters`
8. 带着解析出来的 `<名字>`、`<类型>`、`<引擎>`、字体说明、页数上限、骨架路径、清单路径进 Step 5。**不要重跑 Step 1-4** —— `--use` 换的是**已经登记过**的模板。

## Step 1：模板的类型与来源

问用户（输入里已经答过的就跳过）：

1. **类型：** 这是**简历**模板还是**求职信**模板？
2. **来源：** 模板在哪？下面几种都收：
   - 一个 `.typ` 文件（Typst）或 `.tex` 文件（LaTeX，可以再带 `.cls`/`.sty`）的路径，或者 @ 一下
   - 直接粘过来的 Typst 或 LaTeX 源码
   - 一个目录，里面装着模板和它的附件（类文件、字体、图片）

**给过来的文件全都要读。** 模板引用了标准 TeX 发行版里没有的文档类或宏包（比如自定义的 `.cls`）时，跟用户确认那个文件他有没有；没有就问他要——**缺了它这套模板根本编译不出来**。

---

## Step 2：把用法问清楚记下来

把 `/job-apply` 正确使用这套模板所需要的信息问清楚。**先尽量从源码里自己推**（documentclass、`\fontspec` 调用、页面尺寸、配色），然后把推出来的结果摆给他确认——**不要抓瞎地一条条问**。

要收齐这些：

1. **名字** —— 一个短的连字符标识（如 `awesome-cv`、`classic-serif`）。

   **定下名字后，先跑一次撞名检查**——模板库全 clone 共享，重名即覆盖别人的骨架：

   ```bash
   python tools/template_usage.py --name <name>     # 有人正在用则退出码 1
   ```

   退出码 1 就**换个名字**（加后缀如 `<name>-v2`），不要继续。这一步不是建议：
   覆写会让正在用它的人下次产出**静默改样**，不报错、不提示，直到他自己看出
   排版不对。（原来这里只有散文告诫，没有可执行的检查手段——本仓库在
   `--off-track` 上刚栽过同一形状：`job-rank.md` 写着「要格外克制」，照样误杀了 9 个岗。）

   模板库全 clone 共享，**重名即覆盖别人的骨架**：若 `templates/<type>/<name>/` 已存在，先读它的 `TEMPLATE.md`，把现有模板的引擎/字体/页数摘给用户看，并确认这是「更新我自己注册过的模板」还是「撞名了」——撞名就换个名字（可加后缀，如 `classic-serif-v2`）。不确定时一律换名：同 clone 的其他用户可能正激活着它，覆写会静默改掉他们的产出。
2. **排版引擎**：默认 `typst`。若你的模板是 LaTeX，可选 `xelatex` 或 `lualatex`
   —— 框架支持，但你需要自行安装 TeX 发行版与中文宏包（ctex/xeCJK）。
   选择 LaTeX 时，务必在模板说明中记录所需宏包与字体。
3. **字体** —— 这套模板用了哪些字体、它们从哪来：
   - **随模板附带的字体文件**（`.ttf`/`.otf`）：Step 3 里把它们拷进模板目录，并把 `\fontspec` 调用里用的相对 `Path` 记下来。
   - **系统字体 / TeX 发行版自带的字体**：记下字体名，并注明**用户机器上必须装了它**。
4. **样式规矩** —— 填这套模板时**必须保住**的那些：配色、章节顺序、标题样式、间距惯例、要点的写法、日期格式。
5. **页数上限** —— 编译出来的 PDF **硬性**页数。默认：简历 **2 页**，求职信 **1 页**。`/job-apply` 的「编译 + 检查」循环会照着它卡。
6. **已知的坑**（可选）—— 碰到某类内容就会炸的宏（比如自带模板里 `\lettercontent{}` 与 `itemize` 打架那个）、需要转义的字符、**不许调换顺序**的章节。

## Step 3：把模板存进去

模板库本身（`templates/cv/`、`templates/cover_letters/`）在仓库根、全用户共享，不按
活动用户解析；按活动用户解析的只有激活文件 `templates/active-*.md`。

**共享的代价是会撞名**：隔离的只是「谁激活了哪个模板」这个指针，骨架文件本身是公用的。
写入前再确认一次目标目录不存在（或已按 Step 2 与用户确认过是更新自己的模板）——直接
覆写一个别人注册的同名模板，对方的激活文件仍指向这个路径，下次 `/job-apply` 就会用上你的
字体、引擎和页数上限，而且全程没有任何告警。

建模板目录：

- CV：`templates/cv/<名字>/`
- 求职信：`templates/cover_letters/<名字>/`

往里写：

1. **`template.typ`（typst）或 `template.tex`（LaTeX）** —— 模板骨架。把源文件里所有个人数据
   换成占位符，**占位符名从 `profile.example/candidate.md` 里现取**（`[YOUR_NAME]`、
   `[YOUR_PHONE]`、`[YOUR_EMAIL]`、`[YOUR_CITY]`、`[YOUR_PORTFOLIO_URL]` ……），
   这样模板才可分享、且不绑定某个人。结构、前导、样式原样保留。

   > ⚠️ **别自己编占位符名。** 这里原来举的是 `[YOUR_LINKEDIN_URL]`——那个 token
   > **全仓库只出现在这一行**，资料模板里根本没有领英字段（对应的那项叫
   > `[YOUR_PORTFOLIO_URL]`，「作品集 / 个人主页」）。编一个名字出来，`/job-apply`
   > 填模板时无源可取，那一格要么空着、要么被当成没填完的占位符拦下来。
2. **类文件 / 样式文件** —— 把 `.cls`/`.sty` 一并拷到 `template.tex` 旁边。
3. **`fonts/`** —— 附带的字体文件拷到这里，**目录层级要照 `\fontspec` 的 `Path` 所期望的那样摆**。再把 `template.tex` 里的 `Path` 改成**相对模板目录**的路径。
4. **`TEMPLATE.md`** —— 清单文件。**格式照抄下面这个，不要改：**

```markdown
# 模板：<name>

- **类型：** 简历 | 求职信
- **排版引擎：** typst | xelatex | lualatex
- **页数上限：** <N> 页
- **字体：** <主字体>（<随 fonts/ 附带 | 系统字体，必须先装>）
- **文档类与宏包：** <documentclass 及非标准宏包，没有就写「标准」>

## 编译命令

    typst 引擎：typst compile <file>.typ <file>.pdf
    xelatex / lualatex 引擎：cd <输出目录> && <engine> -interaction=nonstopmode <file>.tex

## 排版规则

- <规则 1：配色、章节顺序、标题样式……>
- <规则 2>

## 已知的坑

- <踩过的坑与它的解法；没有就写「暂无」>
```

## Step 4：**必须**验证它真的编译得过

**没有成功编译过一次，就不许登记。** LaTeX 模板「看着没问题」却编译不出来是常态：字体缺了、类文件缺了、引擎对不上，都会。

1. 把骨架拷成同目录下的一个临时文件（typst 是 `_compile_test.typ`，LaTeX 是 `_compile_test.tex`），把每一个 `[占位符]` 都填上**像真的一样**的假数据（姓名、一行联系方式、一条教育经历、一段带 3 个要点的工作经历——**内容要够把版面撑起来**）。
2. 按所选引擎分支编译。**两个分支都编译第 1 步那份填好假数据的临时文件，
   产物都落在模板目录里**——第 5 步要删的就是它们：
   - `typst` →
     ```bash
     cd templates/<type>/<name> && typst compile _compile_test.typ _compile_test.pdf
     ```
   - `xelatex` / `lualatex` →
     ```bash
     cd templates/<type>/<name> && <engine> -interaction=nonstopmode _compile_test.tex
     ```

   > ⚠️ **typst 那条原来写的是 `typst compile <模板路径> /tmp/template_test.pdf`，
   > 三处都不对，而 typst 正是默认引擎——多数人走的就是这条路。**
   >
   > - **编译的是骨架，不是第 1 步那份填好假数据的临时文件**：`[占位符]` 原样
   >   留在里面，于是第 1 步「填上像真的一样的假数据」对 typst 白做了；
   > - **第 4 步那道版面检查因此是空的**——它要求「以这点假数据来说页数合理」，
   >   而根本没有假数据；
   > - **第 5 步要删的 `_compile_test.pdf` 它从来不产生**（产物去了 `/tmp/`），
   >   于是临时文件建了没用、真产物没人清。
   >
   > 顺带也不再写 `/tmp/`：那是 Unix 路径，而这个仓库在 Windows 上跑得最多。
3. 编译失败：把相关的报错行给用户看，判断病因（字体文件缺失、引擎选错、类文件缺失），能自己修的就修（比如字体的 `Path` 值），然后重编。**修这件事需要只有用户才有的东西时**（缺的字体文件、有授权限制的类文件），**问他要，然后等**。
4. 编译成功后**把 PDF 读一遍**，确认版面确实是正常的（文字没有重叠、字体加载上了、以这点假数据来说页数合理）。**过程中撞见的意外全部记进清单的「已知的坑」。**
5. 删掉试编译留下的临时文件与产物：`_compile_test.typ` / `_compile_test.tex`、`_compile_test.pdf`，以及 LaTeX 引擎产生的 `_compile_test.aux`、`_compile_test.log`、`_compile_test.out`、`_compile_test.fls`、`_compile_test.fdb_latexmk`、`_compile_test.synctex.gz` 等所有 `_compile_test.*` 副产物（typst 只产生 `.pdf`，没有这些中间文件）。

**测试编译不过，就不许进 Step 5。**

## Step 5：激活这套模板

激活时写的是**活动用户的**激活文件（活动用户路径解析见 `AGENTS.md`「活动用户与多用户」）：

- CV 模板 → `templates/active-cv.md`
- Cover letter 模板 → `templates/active-cover-letter.md`

写入前先确认仓库根的 `.active_user` 存在且非空。缺失或为空 → **停下**并引导用户跑
`/job-user`，**不要**退回仓库根写 `templates/active-cv.md`：根级激活文件被 gitignore 兜底，
`git status` 不会提醒，`/job-apply` 也读不到它——你会报告「已激活」，而每次投递都在静默使用
默认模板。

`/job-apply` 起草前先查这个文件，存在即按它；共享指引文件 `05-cv-templates.md`、`06-outreach-templates.md` **从此只读**——不要向它们写任何内容（它们是 git 跟踪的共享框架文件，写入会破坏多用户隔离并触发版本检查）。

从切换模式走到这一步的，用刚才从 `TEMPLATE.md` 解析出来的那份模板信息；从新登记流程走到这一步的，用 Step 2-4 里收集并验证过的那份。

激活文件的内容**照抄下面这份，不要改**：

```markdown
# 激活模板（由 /job-add-template 管理，勿手改）

> **已切换到自定义模板：`<名字>`**
>
> 现在启用的是一套自定义模板。**本块与 `05-cv-templates.md` / `06-outreach-templates.md` 里自带的说明冲突时，以本块为准。** 那两份里讲结构的部分（按岗裁剪、页面预算、怎么删内容）**仍然适用**。
>
> - **骨架文件：** `templates/<类型>/<名字>/template.typ`（typst）或 `template.tex`（LaTeX）—— 结构参照它，不要再参照自带模板
> - **清单：** `templates/<类型>/<名字>/TEMPLATE.md` —— **动笔之前先读它**，样式规矩与已知的坑都在里面
> - **用这个引擎编译：** `<引擎>`（**不是**自带说明里点名的那个）
> - **字体：** <字体说明；附带字体的话，连它的 Path 一起写上>
> - **页数上限：** **不超过** <N> 页（**判的是上限，不是「恰好」**——内容压不满就少写，
>   见 `05-cv-templates.md`「页数」一节）
> - **产物写到哪：** 写入**活动用户的** `documents/applications/<公司>_<岗位>/`（CV 为 `resume.pdf`；cover letter 产出格式见 `06-outreach-templates.md`）；模板要用的 class / 字体文件一并拷进输出目录，或用相对路径引用
```

> ⚠️ **页数那一行原来写的是 `exactly <N> page(s)`。** 这个块自己声明「与自带说明冲突时，**以本块为准**」——于是凡是用了自定义模板的
> 用户，框架早就撤掉的「恰好 N 页」规则又被原样装了回去。而撤它的理由写在
> `05-cv-templates.md` 里：三个不同职业的独立审阅同时指出，对内容量本来只有半页到
> 一页的人（应届生、蓝领技工、刚转行的），「恰好」**主动引导他违反本仓库的诚实底线**
> ——要么编内容，要么删掉诚实标注的缺口。**一个声明自己优先的块，最不该是
> 旧规则的最后藏身处。**

规矩：

- 每类型至多一个激活文件；切换 = 整文件覆写，不叠加。
- **`--use default` 按类型还原**：删掉哪个激活文件就还原哪一类，**绝不默认两个都删**
  （另一类的注册是用户单独做过的，删掉即静默失效）。
  - 用户说了类型（`--use default cv`、「简历换回默认」等）→ 只删对应那一个。
  - 没说类型 → 先看两个激活文件实际存在几个：只有一个 → 删它，并在 Step 6 说明还原
    的是哪一类；两个都在 → 用结构化提问确认（仅简历 / 仅求职信 / 两类都还原），不要
    替用户决定；一个都没有 → 什么都不删，直接告诉用户当前已经是默认模板。
  - 还原后各自生效的默认模板不同：CV → `resume/template.typ`；求职信 →
    `cover_letter/template.typ`（`/job-apply` 5g 内联的就是它，别把简历模板当成两类通用的默认）。
- 不触碰激活文件之外的任何文件。

## Step 6：确认

给出一份小结：

> **模板 `<name>` 已注册并启用。**
>
> - 文件：`templates/<type>/<name>/`（骨架、说明<、文档类文件><、字体>）
> - 试编译：用 `<engine>` 通过了（<N> 页）
> - 以后 `/job-apply` 出<简历 | 求职信>就用这个模板了。启用状态只存在你自己的用户目录里，
>   同一份 clone 的其他人不受影响。
>
> 还能这么用：
> - `/job-add-template --list` —— 看已注册的模板
> - `/job-add-template --use <别的名字>` —— 换一个
> - `/job-add-template --use default` —— 换回默认模板（简历与求职信各自独立还原）

## 设计原则

- **登记是可重复的**：用同一个名字再跑一次，它会问你要不要更新那套已有的模板，而不是复制出第二份。
- **模板存的是不含个人信息的形态**（全是 `[占位符]`），所以它可以分享、可以提交进版本库，不会带出任何个人数据。
- **Step 4 那道编译检查没得商量** —— 一套从没编译过的模板会在 `/job-apply` 跑到一半时炸，而那是最糟糕的发现时机。
- **激活是一个按用户走的文件，不是去改共享说明**：换模板从不碰版本库里的框架文件，每个人的选择互相独立；`--use default` 是一次干净的还原（删掉那一类的激活文件——简历与求职信各自独立还原）。
- 隔离的是**激活指针**，不是模板骨架：`templates/cv/`、`templates/cover_letters/` 全 clone 共享，重名注册会覆盖别人在用的骨架（Step 2 rule 1 的确认就是为此）。
